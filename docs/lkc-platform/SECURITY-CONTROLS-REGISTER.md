# LKC Security Controls Register — editable evidence ledger

**Status:** DRAFT (not compliance certification) · **Baseline date:** 2026-10-10 · **Policy:** [ENGINEERING-SECURITY-STANDARDS.md](ENGINEERING-SECURITY-STANDARDS.md)
**Usage:** Edit **one row per control**, replace owner `TBD`, link actual evidence SHA/PR/run, and use the risk/exception process for blocking items. Do not bulk-switch statuses to PASS after a documentation review.

Implementation is accountable to the named Codex lane/slot holder; Claude reviews independently and does not own or edit the implementation during review. Human security, DB, incident and release roles marked TBD require PO assignment in [PO-DECISIONS-AND-ROLLOUT.md](PO-DECISIONS-AND-ROLLOUT.md). This ledger changes no ownership/slot, GitHub setting or execution permission. Every control row states an intended MUST for applicable operations; deferral/non-applicability requires a reason and the applicable risk decision. Cadence recommendations use SHOULD in the standard.

## Status vocabulary

- `PROPOSED`: rule only; `DOCUMENTED_DRAFT`: documented in unmerged Draft PR; `IMPLEMENTED_UNVERIFIED`: some mechanics exist, full required proof not checked; `REVIEWED_SCOPE` / `CI_PASS_SCOPE` / `DB_PROOF_PASS_SCOPE` / `STAGING_PASS_SCOPE`: positive evidence limited to a precise source revision, environment and test scope.
- `NOT_VERIFIED`: proof unavailable or unchecked; `NOT_RUN`: test/execution did not occur; `BLOCKED`: relevant operation must not proceed; `N/A`: risk-assessed non-applicability, reason mandatory.
- Use flags such as `DB_NOT_RUN`, `MERGE_PENDING`, `RUNTIME_NOT_ACTIVATED` **in addition** to status. A rule's **global** status is never promoted from a passing partial test.

## Control-to-standard mapping policy

This table uses **topic-level** external references, not exact clause conformance claims. The [standard's official-reference table](ENGINEERING-SECURITY-STANDARDS.md#1-authority-references-and-scope) records editions and checked URLs. A future designated security reviewer SHOULD map exact OWASP ASVS requirement IDs with the version prefix (form `v5.0.0-chapter.section.requirement`) and exact NIST SSDF practice/task references to each applicable operation. No extra mapping file is created in SEC-BASE-001. Evidence for one framework must not be relabeled as passing another without examining the corresponding requirement. ASVS target approval remains OPEN.

| LKC scope | External sources to crosswalk | Verification work |
|---|---|---|
| Development & governance | NIST SSDF 1.1, Microsoft SDL, OWASP SAMM | Process owner, policies, review evidence, secure design and training |
| Web/API auth/session/paid reader | OWASP ASVS 5.0.0, OWASP API Security Top 10 2023 | Build versioned requirement ID inventory, actor/action/object/property and tenant tests where applicable |
| CI/Supply chain | SLSA 1.2 Source/Build tracks, OSPS Baseline v2026.08.28 (adapted), GitHub Security | Builder/checkout provenance, least privilege, artifact/source evidence |
| Database/operations | SSDF, SAMM Operations, ASVS relevant data requirements | Real DB test environment, backup/restore/incident drills |
| Market Data/Quant | LKC domain standard + data provider licenses | Lineage, data rights, reproducible replay, model validation |

## Register change policy

1. Update only rows with **new evidence** or confirmed scope changes; append links rather than erasing failures/history.
2. Record a corrected status with timestamp/owner/revision and reason. Reviewer assessment must be independent for source changes.
3. Before risky activation, enumerate all **applicable** C controls, verify each gate and produce a release decision record.
4. A Draft PR into `main` is not production release authorization. The existing `main` deploy workflow may activate on merge.
5. Proposed cadence: owners SHOULD review unverified controls/expiring exceptions monthly and SAMM/threat model/recovery evidence quarterly. The schedule is not evidence those reviews occurred.
