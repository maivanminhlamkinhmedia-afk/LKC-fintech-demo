## 1. Mục tiêu

Biến route \`/creator\` hiện có thành dashboard CMS thực sự dành cho các role có quyền \`cms:access\`.

Dashboard phải cung cấp một màn hình tổng quan an toàn, server-rendered, responsive, hiển thị:

- thông tin Author Profile của user hiện tại
- tổng số bài viết trong phạm vi user được phép thấy
- số bài theo một số trạng thái chính
- danh sách bài viết cập nhật gần đây
- trạng thái profile public/private
- các chỉ dẫn/quick links không dẫn tới route chưa tồn tại

CMS-004 không triển khai editor hoặc CRUD article.

## 3. Authorization

Route \`/creator\` phải được bảo vệ server-side bằng:

\`\`\`ts
await requirePermission('cms:access')
\`\`\`

Không dùng \`content:write\` làm guard chính cho CMS dashboard.

Role được vào dashboard:

- SUPER_ADMIN
- ADMIN
- CREATOR

Role bị deny:

- MANAGER
- SALES_MANAGER
- SALES
- ANALYST
- EMPLOYEE
- CLIENT

Authorization phải dựa trên session server-side.

Không tin role/id từ client.

## 5. Safe scope composition — bắt buộc

CMS-002 đã ghi nhận design risk nếu future caller làm:

\`\`\`ts
{
  ...articleCmsScope(user),
  authorId: someOtherValue
}
\`\`\`

CMS-004 là caller thực tế đầu tiên nên phải compose filter theo cách structurally safe.

Khi thêm filter trạng thái hoặc filter khác, dùng dạng tương đương:

\`\`\`ts
{
  AND: [
    articleCmsScope(user),
    { status: 'DRAFT' }
  ]
}
\`\`\`

Không overwrite ownership scope bằng object spread.

Nếu tạo helper riêng cho dashboard scope thì helper đó phải fail closed.

PUBLISHED
CORRECTED
\`\`\`

Các count phải luôn áp dụng article scope trước.

\`\`\`
