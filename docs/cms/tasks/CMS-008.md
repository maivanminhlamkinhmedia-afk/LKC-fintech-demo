## 4. Catalog contracts và validation

API names có thể điều chỉnh nhưng phải có validator thuần, query server-only, action server, controller/component phân tách. `kind` là enum tĩnh `category|topic|tag|instrument`, không tra Prisma delegate tùy ý từ object key của request.

Mọi input là unknown; chỉ nhận plain own enumerable data properties, đúng allowlist và đủ fields. Từ chối class/array làm object, accessor/getter/setter, symbol, non-enumerable, undefined, extra keys, toJSON/function. Không JSON.stringify/coerce untrusted object trước strict validation. Exception/proxy trap map lỗi an toàn; không hứa có thể kiểm tra Proxy mà không có trap, không thực thi getter hoặc toJSON. Nested ID arrays kiểm dense own data indices/no holes/no extra props/accessors/symbols, primitive strings, trước iteration có thể gọi getter. Error mapper không đọc error getters hoặc raw message.

| Model | Create fields | Mutable update fields |
|---|---|---|
| Category | name, slug, description, sortOrder, isActive | name, description, sortOrder, isActive |
| Topic | name, slug, description, isActive | name, description, isActive |
| Tag | name, slug | name |
| Instrument | name, symbol, instrumentType, exchange, countryCode, currency, isActive | name, countryCode, currency, isActive |

Update thêm expectedUpdatedAt; delete chỉ expectedUpdatedAt. IDs/kind là args được validate riêng. createdAt/id/relations/canonicalKey không nhận từ client. slug và bộ instrumentType+exchange+symbol bất biến sau create; UI readonly identity khi sửa, không submit lại thành mutable fields. Legacy identity đã có giữ nguyên, không tự đổi key hay merge record.

- name: trim/NFC, 1..180 Unicode code points; một dòng, từ chối control characters. Tên trùng được phép; slug/key là unique identity.
- description: null hoặc text trim/NFC tới 4.000 code points; blank → null; giữ newline bình thường; React text, không render HTML.
- slug: trim/lowercase ASCII, 1..120 chars, pattern `[a-z0-9]+(?:-[a-z0-9]+)*`; required. Không tự gọi slugify/external package. UI có thể gợi ý nhưng giá trị submit rõ ràng, server xác nhận.
- Category sortOrder: integer thực trong [-10000,10000]; không NaN/infinity/coerce string/boolean. isActive là boolean thực, không coercion.
- Tags không có active flag: không giả lập cột/soft-delete. Xóa chỉ khi chưa được dùng.
- ID: dùng cùng quy tắc bounded ID hiện hành (ASCII alnum/_/-, 1..191). Token canonical UTC ISO milliseconds, strict round-trip/range như source timestamp; không Date/string coercion tùy ý.
- Duplicate slug trong từng loại hoặc canonicalKey → IDENTITY_CONFLICT an toàn; không trả tên bản ghi khác/SQL/constraint dump. DB unique + transaction là authority; không chỉ client precheck.
- Pre-existing identity có format khác validator mới: render text an toàn, sửa mutable metadata vẫn giữ identity, không auto-repair. Create vẫn tuân chuẩn mới.

### 4.1. Instrument identity — quy tắc của CMS v1

Enum đủ đúng schema: INDEX, EQUITY, FUTURE, ETF, FUND, BOND, COMMODITY, FX, CRYPTO, OTHER.
- symbol: trim/uppercase ASCII, 1..48 chars, `[A-Z0-9][A-Z0-9._/-]*`; không whitespace/control/colon. Không tự suy mã, kỳ hạn, venue hoặc alias.
- exchange: null/blank → null; nếu có trim/uppercase ASCII, 1..32 chars, `[A-Z0-9][A-Z0-9._-]*`.
- FX và CRYPTO trong CMS v1 là cặp/tài sản tổng quát, exchange bắt buộc null. Không định danh theo sàn crypto trong task này.
- Các type khác: exchange tùy chọn; không được dùng exchange reserved FX hoặc CRYPTO.
- countryCode: null hoặc đúng 2 chữ ASCII uppercase. currency: null hoặc đúng 3 chữ ASCII uppercase. Đây là kiểm tra cú pháp; không tuyên bố xác minh registry/quốc gia/tài sản có thật.

CanonicalKey do server sinh, không client override:
- FX → `FX:<SYMBOL>`; CRYPTO → `CRYPTO:<SYMBOL>`.
- Type khác có exchange → `<EXCHANGE>:<SYMBOL>`; không exchange → `<SYMBOL>`.
- Ví dụ VNINDEX, HOSE:VNM, HNX:SHS, NASDAQ:AAPL, FX:USDVND, CRYPTO:BTCUSD khớp schema examples.
- Hai type khác nhau nhưng cùng canonicalKey bị conflict có chủ đích; không tạo identity phân biệt chỉ bằng instrumentType.
- Symbol có dấu '/' khác symbol không có '/' là input khác; không tự deduplicate financial aliases.
- Giữ legacy canonicalKey đã lưu, không re-key các record đang tham chiếu; identity corrections/import thuộc task riêng. UI giải thích identity không sửa được, chưa dùng có thể xóa/tạo lại.
- Không request market data, giá, ticker lookup hoặc liên kết chart để “xác minh”.

## 5. Catalog reads, writes, deletion và concurrency

- Admin list/search không tải toàn bộ catalog vô hạn: page size 25, q trim tối đa 100 code points, kind enum, page positive safe bounded integer (max 100000), malformed page xử lý an toàn theo convention list hiện có.
- Category sort sortOrder ASC/name ASC/id ASC; các loại khác name ASC/id ASC. Search name/slug hoặc name/symbol/canonicalKey qua Prisma parameterized contains; không raw SQL/string interpolation.
- Snapshot count/list cùng filter; page clamp sau count. Admin filter active/all nếu kind có isActive; Tag không có filter active giả.
- Create chỉ tạo một record, default UI rõ isActive=true/sortOrder=0; server validators vẫn đủ fields.
- Update: Serializable TX; fresh actor; đọc row đúng kind/id; expectedUpdatedAt match; conditional write id+token count1; updatedAt=max(Date.now(),previous+1); đọc token persisted phải tăng. Tên/description/sort/active thay đổi KHÔNG sửa Article, không bump hàng loạt Article tokens.
- Metadata update giống hệt canonical current state: success/no-op, giữ token và không write, nhưng vẫn fresh authorization + token check trước. Stale token không được no-op thành success.
- Delete: xác nhận UI; Serializable TX, fresh actor/id/token; kiểm TẤT CẢ references rồi delete exact id+token count1. Có bất kỳ Article/mapping reference → TAXONOMY_IN_USE, không detach, không fallback cascade.
- Category FK SetNull trong schema KHÔNG là quyền tự gỡ category của Article: action phải chặn referenced delete ở mọi Article/status/owner. Instrument primary hay secondary đều là used.
- Deactivate chỉ category/topic/instrument; giữ relations cũ và tokens Article, không unassign. Reactivate cho phép chọn mới lại.
- Concurrent assignment vs deactivate/delete phải có kết quả serializable: assignment commit trước → delete từ chối used; deactivate commit trước → attachment mới bị từ chối; nếu assignment commit trước deactivate, reference inactive được giữ đúng thiết kế.
- Catalog stale write/deadlock/write conflict → EDIT_CONFLICT; không retry server/client âm thầm. P2002 → IDENTITY_CONFLICT; P2003 khi delete → TAXONOMY_IN_USE nếu đúng operation, các lỗi khác map có kiểm soát.
- Post-commit revalidation lỗi → success + warning và canonical ACK, không báo rollback/khuyến khích create lại. Chỉ static error code ở server log.

## 6. Article classification contract

Một thao tác manual Save thay toàn bộ selection snapshot của MỘT Article; không từng checkbox tự ghi:
```ts
{
  categoryId: string | null,
  topicIds: string[],
  tagIds: string[],
  instrumentIds: string[],
  primaryInstrumentId: string | null,
  expectedUpdatedAt: string
}
```

- Category 0..1; Topics 0..5; Tags 0..10; Instruments 0..10.
- IDs trong từng array unique, dense, đúng kind; duplicate bị validation error, không âm thầm cắt/dedup.
- primaryInstrumentId null hoặc thuộc instrumentIds; đúng tối đa một primary. Có instruments nhưng primary=null được phép.
- Server canonicalize thứ tự ID để set comparison; thứ tự checkbox/tìm kiếm không mang ý nghĩa ranking. DTO list order theo name/id, instrument primary được đánh dấu rõ.
- Empty/null arrays là gỡ selections có chủ đích, không xóa catalog.
- Không nhận author/status/body/slug/createdBy/token khác Article.updatedAt. Sources không nằm trong payload.
- Validate existence đúng table; không tự tạo term từ text hoặc nhận identity mới qua assignment.
- Active-only cho attachment MỚI của category/topic/instrument. Term inactive đã attached ở snapshot DB hiện tại được giữ hoặc gỡ; không được gỡ rồi add lại khi inactive. Tag tồn tại là eligible.
- Đổi primary sang instrument inactive vốn đã attached được phép; không thêm một instrument inactive mới.
- Term bị deactivate/delete sau khi mở nhưng trước save: re-read trong TX, không dùng option snapshot client để quyết định.
- Selected inactive hiển thị riêng kèm nhãn, không biến mất vì search chỉ liệt kê active. IDs đang chọn ở page khác/search khác giữ nguyên.
- Catalog read/search cho picker được scope Article/fresh actor trước, không public action/query chỉ nhận arbitrary userId. Read-only Article vẫn hiển thị selected entries; không có mutation control.
- Snapshot Article token + selected relations + selected term metadata phải nhất quán trong cùng transaction. DTO explicit plain object/string/null/array; Dates ISO, không Prisma objects/full contentJson/secrets.
- Legacy selection vượt limits: read đầy đủ, không tự truncate; editable form cho user gỡ để về giới hạn rồi lưu. Multiple primary legacy: hiện cảnh báo, user chọn rõ 0/1 trước save; không tự sửa lúc đọc. Dangling/malformed data không đủ dựng DTO → safe error, không crash/hydrate lỗi hoặc tự repair.

## 7. Assignment transaction và các bề mặt dùng chung token

Trong một Serializable transaction:
1. Fresh actor ACTIVE/role khớp, articleCmsScope, canEditArticleDraft và supported document.
2. Kiểm expected Article.updatedAt; đọc category/current mappings và target terms, kiểm kind/existence/limits/active retention.
3. So sánh canonical desired/current selection. Nếu không đổi: success snapshot/token hiện tại, KHÔNG bump token/insert/delete; vẫn validate quyền/stale token.
4. Nếu đổi: parent CAS id+scope+status+author+editorSchemaVersion+expected token; data CHỈ categoryId và updatedAt=max(now,previous+1); count1.
5. Diff/set mappings của Article đó trong cùng TX; insert/delete exact composite keys, isPrimary true đúng selected ID và false những ID còn lại. Không transient/committed nhiều primary; mọi failure rollback cả parent và mappings.
6. Đọc lại canonical persisted token/relations trong TX và kiểm token đã tăng; ACK là nguồn cập nhật state, không client Date.now().
7. Revalidate sau commit, warning-safe. Không refresh token rồi tự resubmit request stale.

Bất biến được kiểm bằng field-by-field DB snapshot: title/slug/excerpt/body/schema/type/status/author/editor/cover/SEO/lifecycle/createdAt giữ nguyên; source rows và catalog metadata giữ nguyên. Chỉ categoryId, taxonomy mappings và Article.updatedAt đổi.

Concurrency bắt buộc, cả hai commit orders:
- Classification vs classification: đúng một winner cho cùng token, loser giữ input.
- Classification vs autosave/manual body save: same Article token, stale side EDIT_CONFLICT; body hoặc taxonomy winner giữ đúng DB.
- Classification vs source CRUD: same invariant, không tạo một token thứ hai.
- Catalog metadata rename/deactivate không tự biến thành Article mutation; selector phải revalidate eligibility khi save. Race delete/attach xử lý ở mục5.
- Hai race requests thật; không tạo response success giả hoặc bỏ qua auth để test.

## 8. UI/controllers và khả năng phục hồi

Hai form surfaces manual-only (admin catalog và article classification), dùng API hiện có, không dependency mới.
- Catalog: tab/type, search/pagination, empty state, add/edit/cancel/delete; readonly identity; activate/deactivate có nhãn trạng thái; không quảng bá “xóa” như gỡ khỏi bài.
- Classification: labels rõ, category optional, topic/tag/instrument multi-select có tìm kiếm/phân trang, selected summary/chips, primary radio/“Không chọn”, nút “Lưu phân loại” và hủy có confirm.
- Native controls hoặc components có sẵn; không tự viết ARIA combobox thiếu keyboard contract nếu checklist/checkbox phù hợp hơn.
- Không write khi mount/focus/change/blur/search/page/idle. UI state thay đổi không bump token.
- Synchronous single-flight cho mọi mutation của panel; snapshot immutable tại dispatch; disabled pending; catalog add/update/delete không chạy song song. Search read có thể chạy riêng nhưng late results/generation không overwrite selection/form.
- Dirty edit không bị server refresh/search/tab switch đổi baseline/token. Clean newer snapshot mới sync; không nhận older token; unknown result/conflict/terminal giữ draft.
- Known offline: không dispatch, giữ input, online không tự save.
- Validation/identity-conflict/in-use/invalid-selection chưa commit: cho sửa input và manual retry với token đúng. EDIT_CONFLICT/FORBIDDEN/NOT_EDITABLE/UNSUPPORTED_DOCUMENT/NOT_FOUND: stop writes, explicit reload/reconcile.
- Throw/network/INTERNAL_ERROR sau dispatch: UNKNOWN ACK barrier khóa các mutations tới explicit reload (đặc biệt catalog CREATE). Không retry create, không giả rollback. Validation trước dispatch không khóa vô hạn.
- ACK sau unmount/leave/instance change không ghi đè instance mới. finally luôn unlock khi instance còn hợp lệ.
- Hủy/chuyển term/tab/app-link khi dirty hoặc pending phải cảnh báo; native beforeunload giữ đúng hành vi. Chấp nhận rời trang không giả hủy transaction đã dispatch; chỉ chặn follow-up/late UI write.
- Editor → classification link giữ autosave cancel/debounce semantics đã có; classification/source links giữ source dirty guard. Không đổi controller autosave để tắt ghi nhằm pass test.
- XSS: name/description/labels hiển thị React text, không dangerouslySetInnerHTML/link từ text. Search không fetch ngoài origin. UX không hiển thị SQL, table/constraint names, internal IDs như thông báo lỗi.
- 390/768/1280px, labels/fieldset/legend, keyboard và focus, status/error aria-live; long names/symbol/key wrap, không overflow.

## 9. Harness v3, ownership và cleanup

### 9.1. Manifest và creation journal

- New run tạo manifest v3, giữ nguyên 6 QA users, baseline Article plan và namespace per-run hiện có. Sources vẫn exact id+articleId+createdById.
- v3 ghi inventory bốn loại catalogs: exact kind/id/natural identity (slug hoặc canonicalKey), kèm immutable instrument tuple khi có. Seed IDs/keys được tạo từ runId, kiểm absent trước create, create trong cùng setup transaction; fixturesCommitted guard giữ nguyên.
- Những bài classification/SRC mới dùng own per-case Articles, không làm các baseline case nhìn thấy taxonomy bất ngờ.
- Browser catalog CREATE qua UI thật chưa biết ID. TRƯỚC dispatch, harness phải reserve một exact natural-key intent thuộc run: kind, normalized unique slug/key, immutable create identity, expected synthetic create metadata; check-only query xác nhận key absent rồi persist intent. Một namespace string không thay thế intent.
- Khi có ACK hoặc mất ACK, recovery lookup CHỈ exact reserved keys/known IDs, đối chiếu toàn bộ identity; chưa-confirmed CREATE phải khớp initial expected metadata rồi mới adopt returned DB ID. Collision/ambiguous/mismatch → stop; không biến unique-conflict record thành fixture.
- Sau khi known ID đã journal, name/description/isActive/sortOrder có thể đổi đúng UI scenarios, immutable key/id/tuple không drift. Giữ tombstones sau UI delete; không tái sử dụng một natural key đã tombstone trong cùng run.
- Catalog không có creator field: bằng chứng quyền recovery là run-specific pre-reserved identity + pre-create absence + matching record, dưới điều kiện guarded exclusive run. Không tuyên bố chứng minh ai đã tạo một row tùy ý chỉ nhờ title/prefix.
- Intent/journal schemas strict version/keys/kind/run-bound identities; không cho user supplied file thêm bất kỳ arbitrary production ID/natural key. Persist atomically, không password/hash/session/body payload.
- Legacy v1/v2 vẫn đọc theo quyền cũ; không thêm taxonomy fields để nâng quyền, không auto-upgrade. v1 không xóa sources; v2 không xóa catalog/accept taxonomy links. Xử lý v3 explicit ở mọi entrypoint, không rơi vào fallback discoverArticles đơn thuần.

### 9.2. Graph validation/recovery

- Candidate mapping queries theo exact fixture Article IDs OR exact catalog IDs; kiểm CẢ HAI endpoints trước journal/delete. Topic/tag/instrument composite keys ghi rõ; isPrimary là mutable data, không identity.
- Category là FK trong Article: kiểm fixture article.categoryId thuộc approved fixture categories; đồng thời truy ngược ALL articles có categoryId thuộc fixture categories, chặn foreign Article reference.
- Catalog known ID mà slug/key/immutable tuple đổi → stop; known IDs vẫn dùng để phát hiện drift ngay cả khi key đã đổi. Unknown key ngoài intent không được adopt.
- Fixture Article nối đến catalog ngoài fixture hoặc fixture catalog nối đến Article ngoài fixture → stop toàn batch trước destructive writes. Không gỡ foreign references để làm cleanup pass.
- Sau lost ACK assignment, recovery đọc relation graph thật và journal exact approved pairs; không chỉ dựa trên UI ACK. Validate full batch trước bổ sung taxonomy IDs/pairs.
- Source ownership cả hai đầu và known-ID drift vẫn giữ. readFixtureSnapshot/_count allowlist phải đối chiếu exact source/topic/tag/instrument counts, không bỏ mọi relation checks.
- alterFixture chỉ thêm tối thiểu thao tác exact-owned cần kiểm thử (active flag/metadata/token/Article assignments theo contract); không thêm general SQL/global write helper.
- UI tests tìm danh mục theo exact reserved identity; không chọn arbitrary term đang có. Danh mục thật có thể được thấy trong admin list nhưng không được mutate.
- Negative graph/collision/uncertain setup/legacy authorization/rollback tests chạy bằng mocked DB local, không cố tạo foreign production-like links trên staging thật.

### 9.3. Cleanup transaction và counters

- Cleanup CLI mặc định read-only; --apply explicit recovery/guard như hiện có; lock/provenance/port/URL/SQL identity vẫn giữ.
- Xác minh complete graph trước delete. Trong Serializable TX:
  1. SourceReference exact triples.
  2. Mapping exact articleId+topicId/tagId/instrumentId; count khớp. Clear categoryId chỉ trên exact owned Article nếu cần, trong cùng transaction.
  3. Exact fixture login logs, Articles, Users theo guards cũ.
  4. Catalog rows exact kind/id/natural identity/immutable tuple, chỉ khi mọi references đã 0.
- Không dựa FK Cascade/SetNull để che cross-fixture relations; không deleteMany không where, prefix-wide delete hoặc FK disabling.
- v3 verify **13 counters** trong TX VÀ sau commit:
```json
{"articles":0,"profiles":0,"users":0,"logs":0,"sources":0,"categories":0,"topics":0,"tags":0,"instruments":0,"categoryLinks":0,"topicMappings":0,"tagMappings":0,"articleInstruments":0}
```
- categoryLinks đếm Article.categoryId edges; mapping counters bao phủ cả hai endpoints, catalog counters bao phủ known IDs + reserved exact keys (kể cả orphan do mất ACK). Không chỉ đếm IDs đã xóa.
- Legacy recovery giữ output/count contract v1/v2 hiện có (5 counters ở baseline hiện hành); v3 thêm8. Local tests chứng minh không đổi quyền cleanup cũ.
- Failure ở recovery/preflight/transaction/post-commit check → không VERIFIED; giữ manifest, không tự rerun/reset/widen guards.

### 9.4. Browser evidence và vận hành

Giữ 55 baseline cases (20 EDIT +16 AUTO +19 SRC) và assertions thật, bao gồm AUTO-21 native reload trigger, FMT_CODE_BLOCK focus/raw text, native clipboard, shared token DATETIME(3). Thêm TAX cases, tổng discovery =55+N thực tế; ghi N trước staging, không ép một con số chưa implement.

Delta legacy được phép và phải ghi rõ: `tests/e2e/cms-sources.spec.ts` hiện có beforeAll yêu cầu manifest.version===2 và hooks gọi discoverCreatedSources. Khi new run dùng v3, cập nhật đúng version gate/recovery dispatch cho v2/v3 đã validate; không bỏ RUN_PROVENANCE_MISMATCH hoặc nới business assertions. Runner/cleanup hiện cũng có nhánh version===2, phải dispatch v3 explicit. Tests v1/v2 dùng fixture-version setup riêng để tiếp tục chứng minh quyền legacy, không chỉ đổi mọi expected version từ2 sang3 rồi gọi là regression.

Registry/static steps/file locations mở rộng theo exact case inventory; output allowlist/secret suppression/one worker/retries0/screenshot-video-trace off/PLAYWRIGHT_NO_COPY_PROMPT/preserveOutput giữ nguyên. Case/hook/setup failures không bị đổi thành passed hoặc skip để đạt count.

Response barrier chỉ hold/drop ACK của request thật route.fetch; không synthetic auth/success. Request count tách catalog action, classification action, read searches, editor autosave, sources và login bằng route+action identity; search đọc qua Server Action POST không được tính nhầm thành mutation.

DB guards/read/recovery và conditional writes được verify thật ở staging sau review+CI, local mocked tests không đủ. Staging listener chỉ chứng minh cổng mở; kiểm SQL identity trước seed. Nếu hạ tầng mất kết nối, giữ FAIL + cleanup state riêng, theo dõi task cũ tới kết thúc; không coi runId/BUILD_ID/tunnel PID là thay thế bằng chứng cleanup.
