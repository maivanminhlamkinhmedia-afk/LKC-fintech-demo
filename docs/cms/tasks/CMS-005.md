## 4. Ma trận quyền cho task này

| Actor ACTIVE | Tạo | Sửa DRAFT / CHANGES_REQUESTED | Các trạng thái khác |
|---|---|---|---|
| CREATOR | Bài của chính mình | Chỉ own article | Không sửa |
| ADMIN | Bài của chính mình | Mọi article trong read/update:any scope | Không sửa |
| SUPER_ADMIN | Bài của chính mình | Mọi article trong read/update:any scope | Không sửa |
| Các role còn lại / actor inactive | Deny | Deny | Deny |

Giới hạn DRAFT/CHANGES_REQUESTED áp dụng cả ADMIN/SUPER_ADMIN ở editor này để không sửa nội dung đang review/đã xuất bản trước các task workflow. Đây là giới hạn use case, không sửa chính sách canUpdateArticle của CMS-002. ADMIN không được gán lại tác giả; article do SUPER_ADMIN authored vẫn theo article read/update:any hiện có, không áp dụng nhầm quy tắc quản lý AuthorProfile của CMS-003.

Mỗi mutation lấy identity từ session server. Trong transaction, kiểm tra lại User theo session.id: tồn tại, ACTIVE, role còn khớp session và còn đủ permission. Role thay đổi trong lúc edit yêu cầu reload và không ghi bằng quyền cũ. Không lấy actor/owner/role từ input.

Article lookup/write luôn AND composition; không spread scope rồi ghi đè authorId. ID không tồn tại và ID nằm ngoài scope trả cùng NOT_FOUND; không lộ title/slug/author/content của bài người khác. Role bị chặn không được query article trước guard. Không dựa vào việc ẩn nút để bảo vệ mutation.

## 5. Form và dữ liệu được phép ghi

| Field | Quy tắc đã chốt |
|---|---|
| title | String trim, bắt buộc, 1–180 Unicode code points |
| slug | String, normalize tiếng Việt sang ASCII lower-case; 1–150 ký tự, a-z/0-9, dấu gạch nối giữa các nhóm |
| excerpt | String, trim, cho phép rỗng, tối đa 2.000 Unicode code points |
| articleType | Một giá trị ArticleType hiện có; mặc định NEWS trong UI |
| contentJson | JSON object TipTap hợp lệ theo schema bên dưới |
| expectedUpdatedAt | Chỉ khi update: token ISO timestamp do server trả từ lần đọc/lưu gần nhất |

Gợi ý slug từ title ở client đến khi người dùng sửa slug thủ công; server vẫn normalize/validate độc lập. Mapping đ/Đ → d, bỏ combining marks, lower-case, ký tự ngoài a-z0-9 thành dấu gạch nối, collapse/trim gạch nối. Nếu kết quả rỗng hoặc dài quá giới hạn, trả validation error, không âm thầm cắt để tạo collision. Slug không tự đổi theo title sau khi lưu. Không tự đổi sang slug khác khi unique conflict.

Không bắt có AuthorProfile để viết nháp. Chưa có profile không chặn editor.

Server chỉ chấp nhận payload contract đã định nghĩa; thuộc tính ngoài contract trả VALIDATION_ERROR. Không cho input authorId, editorId, status, editorSchemaVersion, contentText, publishedAt, submittedAt, approvedAt, scheduledAt, featured, taxonomy/media/SEO, nested relation writes. articleId là tham số định danh riêng, phải kiểm tra kiểu/độ dài và scope.

Khi create: server đặt authorId = session.id, status = DRAFT, editorSchemaVersion = 1, contentText = derived server text; các field ngoài scope dùng default/null. Khi update: không đổi authorId/status/lifecycle timestamps, chỉ thay các field cho phép, contentText và updatedAt.

## 6. Editor và schema nội dung

Editor là Client Component; authorization/data loading vẫn ở Server Components/Actions. Cấu hình immediatelyRender: false. Tách UI editor khỏi logic server/Prisma. Không thêm 'use client' cho toàn bộ portal.

Toolbar cơ bản: paragraph, H2/H3, bold, italic, underline, strike, inline code, bullet list, ordered list, blockquote, code block, hard break, horizontal rule, undo/redo, đặt/gỡ hyperlink. Undo/redo chỉ trong phiên editor, không phải ArticleVersion history.

StarterKit v3 đã có Link/Underline: không đăng ký extension trùng tên. H1 không được dùng vì title là heading chính. Link chỉ cho http/https tuyệt đối; kiểm tra bằng URL parser phía server, reject credentials/control characters và scheme khác. Không có image, video/iframe, raw HTML, embed, font/color/style tùy ý, citations, table hoặc custom node ngoài spec. Paste phải qua schema editor; không có đường lưu HTML trực tiếp.

Các node được phép: doc, paragraph, text, heading (level 2/3), bulletList, orderedList, listItem, blockquote, codeBlock, hardBreak, horizontalRule. Marks: bold, italic, underline, strike, code, link. Shared schema/config phải dùng nhất quán cho client và server. Những extension hành vi như history không thêm quyền lưu dữ liệu ngoài tập này.

Server validation bắt buộc:

1. Kiểm tra payload types và giới hạn trước khi traverse sâu hoặc tạo ProseMirror document.
2. contentJson serialized UTF-8 tối đa 256 KiB; tối đa 5.000 node, depth tối đa 32; derived text tối đa 200.000 code points. Các giới hạn là constant dùng chung và có boundary tests.
3. Chỉ nhận JSON object/doc root; reject mảng root, null, HTML string, cyclic/non-JSON values và reserved/prototype keys trong object.
4. Reject node/mark/attribute không hỗ trợ, nesting không hợp lệ, heading level khác 2/3, link unsafe. Không dựa vào parser âm thầm bỏ thuộc tính lạ.
5. Validate cấu trúc theo ProseMirror schema trên server, bao gồm kiểm tra content constraints; server không cần DOM/window/Editor browser instance để làm việc này.
6. Canonicalize thành JSON thuần rồi derive contentText từ đúng document đã validate. Text các block/list tách bằng newline, hardBreak thành newline; giữ tiếng Việt và nội dung code. Không tin contentText do client gửi.

Blank body hợp lệ để lưu nháp nếu title/slug hợp lệ: canonical empty document là doc chứa một paragraph trống. JSON + derived text phải được ghi atomically. Đọc article có editorSchemaVersion khác 1 hoặc document không hỗ trợ phải hiển thị lỗi an toàn, không tự migrate/cắt nội dung rồi overwrite bài.

Không lưu raw HTML làm source of truth và không dùng dangerouslySetInnerHTML cho nội dung editor. Không coi JSON hợp lệ là giấy phép render HTML tùy ý ở task public site sau này.

## 7. Create/update và chống ghi đè

Tạo action riêng createArticleDraft và updateArticleDraft; chỉ export entry points async trong file 'use server'. Pure validation/schema/scope/error mapping nằm ở module test được độc lập.

Create chỉ chạy khi người dùng bấm Lưu nháp. GET, mount editor và onUpdate không gọi write. Trong transaction: recheck actor, validate permissions, tạo Article với owner/status do server định. Không tạo ArticleVersion, PublicationEvent, AuthorProfile hoặc workflow records trong task này.

Update phải chống TOCTOU và lost update:

1. Trong transaction Serializable, recheck actor hiện tại và load tối thiểu article trong scope.
2. Kiểm tra canUpdateArticle và status DRAFT/CHANGES_REQUESTED; so expectedUpdatedAt với bản đang lưu.
3. Dùng conditional write với AND gồm id, articleCmsScope(actor), allowed statuses và expectedUpdatedAt. Không chỉ read-check rồi update theo id.
4. Dùng updatedAt hiện có làm optimistic concurrency token; không nhầm editorSchemaVersion thành revision counter. Khi ghi, timestamp mới phải lớn hơn timestamp cũ ở precision lưu thực tế (áp dụng max(Date.now(), previousMilliseconds + 1)); kiểm chứng với MariaDB staging.
5. Số row updated phải bằng 1. Mismatch/token stale → EDIT_CONFLICT, transaction rollback; không trả saved thành công. Transaction serialization/deadlock conflict cũng trả lỗi an toàn và không tự replay dữ liệu cũ.
6. Trả id/slug/updatedAt thực tế sau commit để client dùng cho lần save tiếp theo.

Không tự retry create/update khi kết quả không chắc chắn. Khi create bị mất response, người dùng có thể kiểm tra danh sách; unique slug ngăn tạo trùng cùng slug. UI khóa nút save và editor/form trong thời gian request pending để tránh double submit và trạng thái saved giả khi nội dung đổi giữa request.

Sau lưu thành công, revalidate /creator, /creator/articles và editor route liên quan. Create chuyển tới route edit của article thực sự được tạo. Update giữ người dùng ở editor. Không cache dữ liệu editor giữa các user.

## 8. Lỗi và UX

Kết quả action là discriminated union: ok + data hoặc ok:false + stable error code/message/fieldErrors. Không serialize Error/Prisma error/stack/query/URL vào client.

| Code | Hành vi |
|---|---|
| VALIDATION_ERROR | Lỗi cạnh field/editor; giữ nội dung đang nhập |
| SLUG_CONFLICT | Slug đã được dùng; không lộ bài đang chiếm slug |
| FORBIDDEN | Quyền/role/status không hợp lệ; không ghi |
| NOT_FOUND | Bài không tồn tại hoặc nằm ngoài read scope |
| NOT_EDITABLE | Bài trong scope nhưng trạng thái không được sửa |
| EDIT_CONFLICT | Có thay đổi mới; giữ bản đang nhập, yêu cầu tải lại có xác nhận |
| UNSUPPORTED_DOCUMENT | Schema version/document chưa được editor hỗ trợ |
| INTERNAL_ERROR | Thông báo chung và cơ chế log server không chứa secrets/body |

Chỉ map Prisma unique error sang SLUG_CONFLICT khi ngữ cảnh/constraint đúng slug; không biến mọi lỗi DB thành slug conflict. Unique precheck nếu có không thay thế việc bắt lỗi constraint khi concurrent create.

Giữ requirePermission/redirect/notFound của framework ngoài catch tổng quát; không nuốt redirect thành INTERNAL_ERROR. Expected validation/conflict là trạng thái form, không throw làm hỏng cả trang như bug email trùng ở admin/users đã ghi nhận riêng.

UI phân biệt Chưa lưu / Đang lưu / Đã lưu / Lưu thất bại. Có label truy cập bằng bàn phím, trạng thái toolbar, aria-live cho save result. Nút toolbar type=button. Mất mạng không xóa nội dung hoặc báo saved. Dirty state cảnh báo khi đóng/reload tab và trước các liên kết rời editor do ứng dụng kiểm soát; không lưu bản nháp bí mật vào localStorage, không tuyên bố chặn mọi loại browser navigation.

Responsive kiểm tra editor mới ở 390/768/desktop: toolbar wrap, editor không overflow ngang, code block scroll nội bộ. Không yêu cầu test lại CMS-004 responsive không liên quan.

## 15. Required report và Definition of Done

Codex report phải có: files/dependency versions, server authorization và where/data thực tế, document validation/text derivation, transaction/concurrency, error mapping, editor UX, unit/local validation output, E2E readiness, mapping EDIT-01..24 và AC-01..30, limitations và git status. Tách NOT RUN/STAGING PENDING khỏi PASS; không ghi E2E PASS chỉ vì config build được.

Codex implementation dừng sau report để Claude independent review. Bugs do Codex sửa, Claude regression. Chỉ sau local + independent review + CI + staging/E2E/cleanup PASS và final triage mới merge. Khi merge main, deploy production tự chạy; không migration cho task này.

Production smoke tối thiểu dùng account hiện có: homepage/login/dashboard bình thường; user có quyền mở list/new/editor; role không có quyền bị chặn. Không tự tạo fixture production. COMPLETE chỉ sau spec chốt, implementation/review/regression hoàn tất, tất cả validation gates có bằng chứng, PR merged, deploy SUCCESS, smoke production và monitoring ban đầu không có lỗi mới. Cập nhật ROADMAP.md bằng evidence thực tế, không đổi trạng thái hàng loạt theo suy đoán.
