## 1. Mục tiêu

Triển khai lớp nghiệp vụ Author Profile cho CMS LKC Fintech.

CMS-003 phải sử dụng model `AuthorProfile` đã được tạo trong CMS-001 và nền tảng RBAC đã hoàn thành trong CMS-002.

Task này tập trung vào:

- quyền truy cập Author Profile
- tạo/cập nhật Author Profile
- profile của chính CREATOR
- quản trị profile bởi ADMIN / SUPER_ADMIN
- chuẩn hóa dữ liệu
- public-safe author projection/query
- test bảo mật và validation

Không xây Creator Dashboard hoặc giao diện chỉnh sửa hoàn chỉnh trong task này.

---

## 2. Source of truth hiện tại

Model đã tồn tại:

`prisma/schema.prisma`

```prisma
model AuthorProfile {
  id          String   @id @default(cuid())
  userId      String   @unique
  displayName String
  slug        String   @unique
  jobTitle    String?
  bio         String?  @db.Text
  avatarUrl   String?  @db.Text
  expertise   String?  @db.Text
  publicEmail String?
  isPublic    Boolean  @default(true)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  user User @relation("AuthorProfileUser", fields: [userId], references: [id], onDelete: Restrict)
}
```

CMS-003 không được thay đổi model này nếu không phát hiện blocker cụ thể.

Dự kiến không có Prisma migration.

## 3. Role trong phạm vi

Các role có thể sở hữu Author Profile qua application layer:

```text
SUPER_ADMIN
ADMIN
CREATOR
```

Các role sau không được tạo/quản trị Author Profile trong CMS-003:

```text
MANAGER
SALES_MANAGER
SALES
ANALYST
EMPLOYEE
CLIENT
```

Nếu một AuthorProfile cũ tồn tại cho user đã bị đổi sang role không còn hợp lệ, public lookup phải fail closed và không expose profile đó.

## 4. Permission reuse

Không thêm permission mới nếu không có blocker.

Tái sử dụng:

```text
cms:access
cms:admin
```

Quy tắc:

- CREATOR dùng `cms:access` + ownership của chính user
- ADMIN dùng `cms:admin`
- SUPER_ADMIN dùng `cms:admin`

Không tạo:

```text
cms:author:*
```

trong CMS-003.

---

## 5. Quyền self-service của CREATOR

CREATOR đã đăng nhập được phép:

- đọc AuthorProfile của chính mình
- tạo AuthorProfile của chính mình nếu chưa có
- cập nhật AuthorProfile của chính mình
- bật/tắt `isPublic` cho profile của chính mình

CREATOR không được:

- đọc profile private của user khác qua back-office helper
- tạo profile cho user khác
- cập nhật profile user khác
- truyền `userId` từ client để thay đổi ownership
- thay đổi role user
- tạo profile cho non-CMS user
- hard delete AuthorProfile

Identity cho self-operation phải lấy từ authenticated server session.

---

## 6. Quyền của ADMIN

ADMIN được phép:

- đọc AuthorProfile của CMS author hợp lệ
- tạo AuthorProfile cho:
  - ADMIN
  - CREATOR
- cập nhật AuthorProfile của:
  - ADMIN
  - CREATOR
- cập nhật profile của chính ADMIN

ADMIN không được quản trị AuthorProfile của SUPER_ADMIN khác.

ADMIN cũng không được dùng CMS-003 để thay role hoặc trạng thái User.

---

## 7. Quyền của SUPER_ADMIN

SUPER_ADMIN được phép:

- đọc mọi AuthorProfile thuộc CMS author hợp lệ
- tạo AuthorProfile cho:
  - SUPER_ADMIN
  - ADMIN
  - CREATOR
- cập nhật các profile trên

SUPER_ADMIN không được hard delete AuthorProfile trong CMS-003.

---

## 8. User eligibility

Tạo/cập nhật AuthorProfile chỉ hợp lệ khi target User:

- tồn tại
- có role thuộc:
  - SUPER_ADMIN
  - ADMIN
  - CREATOR

Đối với write operation, target User phải có:

```text
status = ACTIVE
```

Không tạo hoặc cập nhật profile cho User:

```text
INVITED
SUSPENDED
DISABLED
```

Nếu user trở thành non-author role hoặc không ACTIVE sau này, dữ liệu AuthorProfile có thể vẫn được giữ để bảo toàn lịch sử, nhưng public lookup phải không expose profile đó.

Không tự động xóa profile khi role/status thay đổi.

## 9. Field rules

### displayName

- bắt buộc
- trim whitespace
- không được rỗng sau trim
- độ dài tối đa 120 ký tự

### slug

- bắt buộc ở dữ liệu persisted
- phải được canonicalize server-side
- lowercase
- chỉ cho phép:
  - `a-z`
  - `0-9`
  - `-`
- loại bỏ dấu tiếng Việt
- chuyển `đ` / `Đ` thành `d`
- whitespace và separator liên tiếp phải collapse thành một dấu `-`
- bỏ dấu `-` ở đầu/cuối
- tối thiểu 2 ký tự
- tối đa 120 ký tự
- phải unique toàn hệ thống

Ví dụ:

```text
"Nguyễn Văn Minh" -> "nguyen-van-minh"
"Đỗ Thị Hà"      -> "do-thi-ha"
```

Không tin slug đã canonical từ client.

Server luôn canonicalize lại trước persistence.

### jobTitle

- optional
- trim
- empty string -> null
- tối đa 160 ký tự

### bio

- optional
- trim
- empty string -> null
- tối đa 5000 ký tự

### avatarUrl

- optional
- trim
- empty string -> null
- nếu có, chỉ chấp nhận URL absolute với protocol:
  - `http:`
  - `https:`

Không chấp nhận:

- `javascript:`
- `data:`
- `file:`
- relative URL

Media Library chính thức thuộc CMS-009; CMS-003 chỉ lưu URL string an toàn.

### expertise

- optional
- trim
- empty string -> null
- tối đa 2000 ký tự

### publicEmail

- optional
- trim
- lowercase
- empty string -> null
- validate email cơ bản
- tối đa 191 ký tự

Không tự động copy `User.email` vào `publicEmail`.

### isPublic

- boolean
- default khi tạo mới: `true` nếu input không chỉ định
- không nhận string truthy/falsy mơ hồ từ client

## 10. Slug collision

Nếu slug đã tồn tại cho AuthorProfile khác, operation phải fail rõ ràng.

Không được:

- overwrite profile khác
- tự append suffix ngẫu nhiên không được spec cho phép
- silently change slug

Có thể map Prisma unique conflict `P2002` thành domain error rõ ràng.

Không expose raw database error hoặc stack trace tới UI caller.

---

## 11. Slug update policy

CREATOR:

- được phép thay slug của profile chính mình trong CMS-003
- nhưng vẫn phải canonicalize và unique-check server-side

ADMIN / SUPER_ADMIN:

- được phép thay slug của target profile trong phạm vi quyền

CMS-014 có thể bổ sung SEO/redirect policy sau này.

CMS-003 không tạo redirect history.

Ẩn profile khỏi public surface bằng:

```text
isPublic = false
```

Không xóa row để bảo toàn liên kết lịch sử.

## 13. Public-safe author profile

CMS-003 phải cung cấp reusable public query/projection.

Ví dụ hành vi tương đương:

```text
getPublicAuthorProfileBySlug(slug)
```

Public lookup chỉ được trả profile khi tất cả điều kiện đúng:

- AuthorProfile.slug match canonical slug
- AuthorProfile.isPublic = true
- User.status = ACTIVE
- User.role thuộc:
  - SUPER_ADMIN
  - ADMIN
  - CREATOR

Nếu một điều kiện không đúng:

```text
return null
```

Không throw authorization detail ra public.

## 17. Self upsert

Cung cấp operation hành vi tương đương:

```text
upsertMyAuthorProfile(input)
```

Quy trình bắt buộc:

1. authenticate server-side
2. require `cms:access`
3. actor phải là CREATOR, ADMIN hoặc SUPER_ADMIN
4. target user id luôn lấy từ session user id
5. load User server-side
6. validate User role/status
7. normalize input server-side
8. upsert AuthorProfile theo `userId`
9. không nhận ownership từ client

Nếu ADMIN/SUPER_ADMIN dùng self-upsert thì vẫn target chính họ.

---

## 18. Admin upsert

Cung cấp operation hành vi tương đương:

```text
upsertAuthorProfileForUser(targetUserId, input)
```

Bắt buộc:

1. authenticate server-side
2. require `cms:admin`
3. actor id/role lấy từ session
4. targetUserId có thể đến từ request nhưng không được tin quyền của nó
5. load target User server-side
6. check target eligibility
7. enforce hierarchy:
   - ADMIN không được quản trị SUPER_ADMIN khác
   - SUPER_ADMIN được phép
8. normalize input
9. upsert theo `userId`

Không cho client truyền target role/status để bypass DB lookup.

---

## 19. Concurrency / uniqueness

AuthorProfile có:

```text
userId @unique
slug   @unique
```

Write implementation phải an toàn với race cơ bản.

Ưu tiên dùng Prisma `upsert` theo `userId` khi phù hợp.

Slug unique conflict phải được xử lý rõ.

Không thực hiện read-then-create không an toàn nếu có thể dùng upsert.
